## Что важно знать владельцу

### 1. ADB даёт root сразу

```
$ adb shell id
uid=0(root) gid=0(root) ...
```

На устройстве стоит `SuperSU` (`com.koushikdutta.superuser`, `/system/xbin/su` с битом
`-rwsr-x---`). Это означает: **любое устройство в вашей сети, подключившееся на порт 5555,
получает полный контроль над проектором без единого запроса на экране.** Не «может получить
при отладке» — получает сразу.

Что с этим делать:

- после работы выключить отладку по ADB в меню разработчика;
- проверить, что порт закрыт: `python3 tools/adb-closed.py 192.168.1.50`;
- не пробрасывать порт на роутере;
- если проектор стоит в офисе или общежитии — считать его полностью открытым, пока отладка включена.

`ro.adb.secure` пуст — это заводская особенность прошивки, не следствие наших действий.

## Прошивка: обновлять нечего

Проверено 17.11.2026 через штатное приложение самого проектора
(`com.droidlogic.updater` → «ПРОВЕРИТЬ ОБНОВЛЕНИЕ СИСТЕМЫ»).

Ответ устройства на экране: **«Онлайн-обновление: Нет обновлений»**.

Что это значит и почему я ничего не менял:

| Факт | Значение |
|---|---|
| Установлено | `be311-13 TQ2A.20260716 16:07:36.E1`, сборка от 16.07.2026 |
| Канал обновлений | `persist.sys.proxy.url = https://apk.v8ying.com/ota.bin` — вендорский сервер |
| Сервер отвечает | да, `HTTP 200`, но манифест зашифрован (367 байт) и новых версий не предлагает |
| Патч безопасности | `2023-04-05` — очень старый, это прошивка вендора, а не Google |

Отпечаток сборки подменён: `ro.build.fingerprint` = `google/redfin/redfin:12/...` — это Pixel 5,
хотя платформа Amlogic/DroidLogic. Обычная практика у мелких производителей: fingerprint
копируется, чтобы прошли проверки совместимости. На обновления это не влияет, но и доверия
к такой прошивке не добавляет.

**Вывод:** обновлять нечего, и принудительно — нечем. Прошивка обновляется только файлом
с флешки через «ОБНОВИТЬ ЛОКАЛЬНО», если вендор выложит образ. Сам я такой образ ставить
не стал бы: сборка не подписана известным ключом, откат при неудаче невозможен, а выигрыш
неясен. Патч безопасности 2023 года при этом остаётся — это единственный реальный минус,
и он не лечится средствами Android TV.

Если вендор выпустит обновление, его можно поставить так: скачать образ на флешку (FAT32),
вставить в проектор, открыть это же приложение → «ОБНОВИТЬ ЛОКАЛЬНО» → выбрать файл.
Через ADB прошивку не обновляют.

## Лончер «Дом» установлен (18.11.2026)

Собран и поставлен на проектор: `com.gathin.tvhome` v3.5, APK 575 КБ (minSdk 26, targetSdk 34).

Главная сложность оказалась не в сборке, а в том, что прошивка **не даёт сменить домашний экран
обычным способом**. На этом устройстве три лаунчера, и работают сразу два механизма:

1. `com.master.t972` — заводской, системный, с `RECEIVE_BOOT_COMPLETED`; при загрузке сам
   захватывает экран раньше, чем система спросит про выбор Home.
2. `com.jm.jmlauncher` (`/system/app/JmLauncher`) — второй системный лаунчер, который слушает
   **собственную категорию** `android.intent.category.HOME.JM`, а не стандартную `HOME`.
   Поэтому `cmd package set-home-activity` его вообще не видит.
3. Настоящий переключатель — prop прошивки: `persist.sys.home.selectpkg`. Пока там стоял
   `com.master.t972`, любой Home возвращал заводской экран.

Что сделано:

```
setprop persist.sys.home.selectpkg com.gathin.tvhome     # главное
pm disable-user --user 0 com.master.t972                 # заводской экран
cmd package set-home-activity --user 0 com.gathin.tvhome/.MainActivity
```

Проверено перезагрузкой: `Дом` запускается сам, в фокусе, PID живой.

### Главный экран: четыре приложения (18.11.2026)

По просьбе владельца главный экран сведён к минимуму:

| На главном | |
|---|---|
| YouTube | `com.google.android.youtube.tv` |
| HDrezka | `com.falcofemoralis.hdrezkaapp` |
| Zona | `mobi.zona` |
| Rutube | `ru.rutube.app` |

**Полный список приложений — одно нажатие «вниз»** с главного экрана. Раньше требовалось два
(«вниз» наводило на кнопку списка, потом OK), поэтому в лончер добавлена настройка
`library_on_down`: она сразу открывает «Библиотеку приложений» — сейчас там **26 приложений**,
включая те, что скрыты с главного (Chrome, VLC, файловый менеджер, часы, настройки, happ и другие).

Как это устроено в конфиге:

- `dock_apps` — четыре пакета выше;
- `hidden_apps` — 22 пакета, которые не показываются плитками на главном, но **остаются**
  в полном списке (диалог библиотеки не учитывает `hidden_apps`);
- `app_library` = true и `show_library_pill` = true — сам список и вход в него;
- `library_on_down` = true — вход одним нажатием.

Вернуть приложение на главный экран можно прямо с пульта: в библиотеке «нажать — добавить
на главный экран», «удержать — опции».

### Как поменять набор на главном

Правки в `launcher/app/src/main/res/values/config.xml`, затем пересборка и установка:

```bash
cd launcher && ./gradlew assembleRelease
cd .. && TV_HOST=192.168.1.50 SKIP_BUILD=1 STOCK_LAUNCHER=none ./launcher/install_launcher.sh
```

- добавить приложение в док — вписать пакет в `dock_apps`;
- убрать с главного — добавить пакет в `hidden_apps`;
- вернуть приложение в полный список, если его там нет, — убрать из `library_excluded_apps`.

Быстрее всего с пульта: «вниз» → «Библиотека приложений» → навести на приложение →
**нажать** (добавить на главный) или **удержать** (опции).

### Откат

```bash
setprop persist.sys.home.selectpkg com.master.t972
pm enable com.master.t972
```

или `python3 tools/restore.py --home`.

| Ярлык | Пакет | Путь | Размер |

| MoviePlayer | `com.droidlogic.videoplayer` | `/system/priv-app/VideoPlayer/` | 10 МБ |
| DLNA | `com.droidlogic.mediacenter` | `/product/app/DLNA/` | 3,9 МБ |
| Okko | `ru.more.play` | `/data/app/` | 43 МБ |
| Яндекс Музыка | `ru.yandex.music` | `/data/app/` | 50 МБ |
| Chrome | `com.android.chrome` | `/data/app/` | 102 МБ |

Итого освобождено ≈213 МБ. Пакетов было 135, стало 130.

**Okko оказался `ru.more.play`** — ярлык в системе не совпадал с именем пакета, опознан
запуском и по `ActivityRecord` в `dumpsys activity`.

### Почему это было безопасно

- **WebView не пострадал:** системный движок — `com.android.webview` 131.0.6778.200,
  а не Chrome. Страницы внутри приложений (в том числе магазины) работают.
- **Видео и звук целы:** 42 кодека на месте, `STREAM_MUSIC` активен, 13 ТВ-входов
  (`com.droidlogic.tvinput`) работают — HDMI и AV не тронуты.
- **Крашей нет:** `logcat -b crash` пуст после перезагрузки.

### Как удалялись системные APK

Разделы `/system`, `/vendor`, `/product` смонтированы только на чтение, но поверх них
включён **overlayfs** с записываемым слоем в `/mnt/scratch/overlay`. Поэтому файлы
удаляются обычным `rm` после `mount -o rw,remount`, а после перезагрузки пакеты
исчезают из реестра. Откат — установка APK из `apk-backup/` обратно.

## VPN Happ: ключ установлен (18.11.2026)

Ключ подписки (`https://<сервер-подписки>/<ключ>`) добавлен в Happ 4.7.1 и проверен.
В репозитории сам ключ не публикуется: подписка личная и привязана к устройству.

**Результат:** подключение работает. Внешний IP — зарубежный хостинг (OVH, Варшава).
Скорость ~6 Мбит/с, DNS работает, три проверки подряд дали один и тот же IP.

### Важно: подписка привязана к устройству (HWID)

Подписка отдаёт **заглушку, а не серверы**, если клиент не прислал свой HWID в заголовке
`x-hwid`. Проверено напрямую:

| Запрос | Что отдаёт сервер |
|---|---|
| без заголовка | 3 заглушки `vless://0000…@0.0.0.0:1` |
| `x-hwid: <android_id проектора>` | 3 заглушки |
| `x-hwid: <нужный HWID>` | **14 реальных серверов** |

Заглушки подписаны «⚠️ Приложение не поддерживается», «👇 Воспользуйтесь инструкцией»,
`@extravpn_robot`. Срок подписки — до 07.12.2026, объявление: «Осталось 19 дней».

Поэтому обычное добавление ссылки в Happ давало мёртвый сервер `0.0.0.0:1`: туннель
поднимался (`tun0` = 26.26.26.1), но трафика не было вообще — ни HTTP, ни DNS.

### Что сделано

Вместо подписки добавлен **прямой VLESS-ключ польского сервера** (Reality, xtls-rprx-vision,
`pl.extra-solutions.ru:443`). Команда:

```bash
am start -a android.intent.action.VIEW -d "happ://add/vless://…@pl.extra-solutions.ru:443?…"
am start -a android.intent.action.VIEW -d "happ://connect"
```

Живые серверы подписки: Польша, Латвия, Чехия, Норвегия, Швеция, Франция, Британия, США.
**Эстония (`ee.extra-solutions.ru`) не отвечает** — не выбирайте её.

### Ограничение

VPN **не поднимается автоматически после перезагрузки** — Happ не получил разрешение
на постоянный VPN. После включения проектора нужно открыть Happ и нажать «Подключить»
(или выполнить `happ://connect` по ADB). Настройки при этом сохраняются.

### Кнопка VPN на главном экране (18.11.2026)

В верхней панели появилась кнопка VPN в ряду **Источники → Wi-Fi → VPN → Настройки**:

| Состояние | Надпись | Что делает OK |
|---|---|---|
| VPN поднят | `VPN` (зелёная с замком) | выключает VPN |
| VPN опущен | `VPN отключён` (красная) | включает VPN |

Одно нажатие на пульте переключает соединение и **само возвращает на главный экран** —
приложение VPN остаётся в фоне, искать в нём кнопку не нужно.

Устроено на встроенной в лончер пилюле `btnVpn`. В `config.xml` включено:

```xml
<string name="vpn_app" translatable="false">com.happproxy</string>
<bool name="vpn_pill">true</bool>
<string name="vpn_toggle" translatable="false">happ://toggle</string>
```

`vpn_toggle` — новая настройка: deep link, который переключает VPN. У Happ это `happ://toggle`.
Если оставить её пустой, кнопка просто открывает приложение, как было задумано в оригинале.

**Важно:** `happ://toggle` поднимает окно Happ поверх лончера. Поэтому через 1,2 секунды
лончер сам вызывает `ACTION_MAIN` + `CATEGORY_HOME` и возвращает владельца на главный
(`comeBackHome()` в `MainActivity`), но только если окно лончера уже потеряло фокус —
если пользователь успел уйти в другое приложение, его не дёргает.

### Первое нажатие после перезагрузки

VPN не поднимается сам после включения проектора. Кнопка на главном решает это: одно
нажатие — и соединение есть, без захода в Happ.
